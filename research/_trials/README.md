# 试跑（研究自动循环）

筛选出的候选先不开题，在这里试跑（TRADING-2565 试跑模式，`owner_decision:TRADING-2565:2026-10-15:trial_mode`）。主配置在两个市场的开发窗口都过门，才交 owner 评估是否开题；试跑从不读验证窗口。

## 文件

| 文件 | 内容 |
|---|---|
| `prereg.yaml` | 试跑的门（C 区）：两个市场、每个市场的规则、每份计划最多几个配置、bootstrap 置信度。改它要新的 owner 决定 |
| `T0001.yaml` 等 | 试跑计划，一个候选一份：信号和筛选记录、假设卡、想法是否来自验证窗口、两份快照、配置和主配置 |
| `runs/NNNN.json` | 试跑记录：哈希链，只追加，失败的也记；和 `research/*/runs/` 一样走研究记录快车道 |

## 两个市场

- QQQ：开发窗口 1999-03-10 到 2010-12-31，真实 QQQ（长历史快照），规则同第三题的 11 条（左尾、回撤、几何年化、成本、推迟、逐年和逐段剔除、同敞口随机择时）。
- 美股大盘：Ken French 日度市场收益（`ff_factors_daily` 的 Mkt-RF 加 RF），开发窗口 1929-01-02 到 2010-12-31，4 条规则：回撤、左尾、25 bps 成本、推迟两天的左尾。6 个快跌段（1929、1962、1987、1998、2000–2002、2007–2009）只在报告里看，不判。2 倍、3 倍按日合成、不扣费，只为让模拟器有完整的列；试跑配置的敞口在 0 到 1，不持有它们。

## 规则

- 计划写在任何试跑之前。每次运行记下计划和门的 SHA-256；跑过以后计划变了，评估台拒绝：改了就是新假设，从新的假设卡开始，另起计划号。
- 一个信号只能在一份计划里；计划里钉住的信号模块或规格变了，拒绝。
- 门和计划必须和 main 上的一样，决定号必须在 main 的 `docs/requirements` 里，筛选记录必须在筛选账里、筛的是计划里的信号，否则拒绝。拒绝的运行不记账。
- 同一配置在同一市场成功跑过一次，就不再跑；出错或检查没过的可以再跑，每次都记。
- 判定只看主配置：两个市场都过门是"过门"，任一市场没过是"没过"，否则"未完成"。其他配置只做敏感性，计入试验数，不决定。
- 每个配置都算一次试验：全局总试验数是各题开发试验加试跑配置数。没过的候选只记在筛选账和试跑账里，不进 `negative_results.md`（第 1 期章程）。

## 命令

命令都是 `python -m ai_trading_system.research_bench ...`，输出只有汇总。

- `trial-run T0001 --config primary --market qqq|us_market [--root 快照目录]`：在一个市场的开发窗口上跑一个配置，按门判，登记。
- `trial-ledger`：链检查、每份计划的运行和主配置判定、全局总试验数。
- `trial-report T0001`：候选包的第一页：计划摘要、每次运行的规则表、美股大盘快跌段、判定、试验数，以及再读验证窗口时的显著性 0.05/k。
