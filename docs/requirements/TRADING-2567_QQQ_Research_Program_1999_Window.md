## S1、S2 的实现（2026-10-12）

数据：
- 模块 `src/ai_trading_system/research_data/qqq_long_history.py`，规格 `config/research/qqq_long_history.yaml`，数据源目录登记为 `fred_qqq_long_history_research`（新领域 `research_history`，不参与 market_prices、macro_rates 的跨源对账，不进日报）。
- `python -m ai_trading_system.research_data.qqq_long_history fetch`：用现成的 `FredRateProvider` 下载 1986-01-01 起的 6 个序列，写成 `data/raw/research/qqq_long_history/<快照 id>/`（`series.csv`、`manifest.json`）。快照 id 由请求截止日和内容 sha256 组成，同样的数据得到同样的 id。下载后自动检查。
- 在主仓库运行，研究代码默认从主仓库读快照；`--prices-path` 指向运行副本里最新的 `prices_daily.csv`，只读。运行副本只由计划任务和 9.1 版本更新写，不放研究数据。
- `check`：校验和、各序列首日不晚于规格（FAIL）、重复日期、指数水平为正（FAIL）；单日涨跌超 25%、超过 5 个日历日的间隔（9/11 休市已登记）、利率和波动率指数越界、价格有变动却没有总收益的日子、21 个交易日窗口里总收益落后价格收益超过 0.5%、序列停更（WARN）；逐年列出总收益落后价格收益超过 0.05% 的天数、隐含股息率、日股息分量的标准差和噪声归属（总收益日收益对日股息分量的斜率：约 1 表示噪声在总收益指数，约 0 在价格指数，约 0.5 是两个都有或某个指数的收盘时间不对），以及总收益滞后系数（总收益日收益对价格指数当天和前一天收益回归，前一天的系数：约 0 没有滞后，正值是总收益指数有这部分涨跌晚一天才反映，负值是价格指数滞后），低于下限的窗口里的交易日也合起来各算一次；派生后与本机 `data/raw/prices_daily.csv` 的 QQQ、QLD、TQQQ 复权价比重叠段的年化跟踪差和跟踪误差，超出容差记 WARN。结果写 `check.json`、`check.md`，只含汇总。
- 研究代码只能经 `load_daily` 读：快照校验和不符、没有检查、检查结果是 FAIL、或规格在检查后改过，都拒绝读取。这就是这份数据的质量门禁，相当于日报缓存的 `aits validate-data`。
- 派生（以 Nasdaq-100 价格指数的交易日为日历，总收益指数开始后去掉价格指数单独有值的日子；一个指数沿用前值而另一个变动时，按另一个的变动修补；按两个交易日之间的日历天数计息）：QQQ 代理 = 总收益指数日收益 − 0.20% 年费率；现金 = 前一交易日的 DTB3 × 天数/360；合成 L 倍 = L × 总收益指数日收益 − (L−1) × (前一交易日 DTB3 + 1.25% 融资利差) × 天数/360 − 0.95% 年费率 × 天数/365。费率是事先定的；融资利差原定 0.5%，第一次快照检查后按 TQQQ 的实际跟踪差改为 1.25%（见进展）。
- 检查报告不给任何窗口上的收益或择时结果，避免在预注册之前读到验证窗口的结论。

窗口：
